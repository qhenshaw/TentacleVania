# UI

Runtime UI (`TentacleVania.UI`), all UI Toolkit.

Static screen text that's set once in code must go through `Fonts/UiText.Bind(element, key)` (re-applied when the locale changes); per-open text can use plain lookups. Labels and buttons use `min-width` (not `width`) and tab rows wrap, so longer languages grow instead of clipping. `Hud/LoadoutHudView` fills the slot key hints from the current bindings.

## Main menu

- `Menu/MainMenu.prefab` (in the `MainMenu` scene) is a `UIDocument` on `MainMenuPanelSettings` (1920×1080 scale-with-screen) with `MainMenuScreen`. Buttons: Continue (only when a save exists; loads the most recently saved slot, `Core.Saves.SaveSlots.MostRecent`), New Game and Load Game (both open the 5-slot list: sector, level and playtime per slot, Delete with a confirm; New Game asks before overwriting a slot and saves the new slot at once), Settings, Quit. Cancel backs out of the confirm, then the list. Loading goes `SaveSystem.Load` then `SceneFlow.Load(SaveSystem.RunScene)`; New Game also loads `Run` (developer decision: roguelike only). From an eval: `MainMenuScreen.Instance.Play()` (Continue, else a new game in the first empty slot), `OpenSlots(newGame)`, `ChooseSlot(i)`, `DeleteSlot(i)` then `Confirm()`. Play-testing it writes real saves under `Application.persistentDataPath/Saves`: back the folder up first and restore it.
- Player-facing text comes from string tables (`Assets/Game/Localization/`); set a key in UXML by name and bind it in code, never write the text in UXML or C#. Debug menu labels are exempt.

## Settings

- `Settings/SettingsScreen.prefab` (nested in `MainMenu.prefab` and `CombatHud.prefab`; its own `SettingsPanelSettings`, sort order 100, so it draws over everything) is the settings screen. Main menu Settings button, F5 HUD tab "Open settings"; the pause menu (TV-83) should call `SettingsScreen.Instance.Open(onClose)`.
- **Tabs:** Audio, Gameplay (assists, keep biomass), Accessibility (shake, flashes, gore, rumble, subtitles, colour-blind mode), Controls, Display and Language. Rows are built in code from `UI` table keys (`settings.*`, `action.*`).
- **Behaviour:** every change writes `Core.Settings.SettingsStore.Data` and calls `Apply`; closing (Back, or cancel) saves. Reset tab restores one tab's defaults. While it's open, creature control is locked.
- **Rebinding:** Controls lists Weapon 1/2, Dash, Grab and Ability with one button for the Gamepad binding and one for Keyboard&Mouse. Pressing one starts `PerformInteractiveRebinding` (Esc cancels; mouse movement excluded) and saves when done.
- **Pitfall:** an eval that opens the screen or calls `SettingsStore.Save` overwrites the developer's real `settings.json` (closing saves, and so does play exit while it's open). Back the file up and restore it, or delete it, before play ends.
- **Pitfall:** the UIDocument root must `StretchToParentSize()`, or the full-screen backdrop and panel collapse to zero height.

## Combat HUD

- `Hud/CombatHud.prefab` (one per gameplay scene, in `CombatArena`) is a `UIDocument` on `HudPanelSettings` with `CombatHud`, which updates in `LateUpdate` without allocating (enemy bars are a fixed pool of 32 built in `OnEnable`). Developer decisions: player health over charge at bottom-centre with no text; boss bars will go at the top; no combo-step display.
- Player health uses `BarTrail` (unit tested): damage drops the fill at once and leaves a pale chunk that drains after 0.5 s; heals show a green segment that the fill catches up to. Charge turns bright cyan and pulses when full.
- Enemy bars (HP with a grey armour strip, amber stagger under it) follow `EnemyManager.Current` enemies at agent height + 0.5 m, appear on any HP, armour or stagger change and fade 4 s later. An enemy under the grab threshold (`Enemy.IsFeedable`) keeps its bar shown with a pulsing green fill.
- Shared runtime theme: `RuntimeTheme.tss`; both the menu and HUD panel settings use it.
- `Hud/InteractionPromptView` (on `CombatHud.prefab`) shows `Core.Interaction.Interactions.Current`'s `PromptKey` from the `UI` table in the `prompt` label above the player bars, hidden (`hud__prompt--hidden`) when there is none; keys so far: `prompt.nest.grow`, `prompt.nest.rest` ("Tap: checkpoint · Hold: rest"). For an `IHoldInteractable` a small `HoldRing` sits just right of the text (placed from `MeasureTextSize`, since the label's own box doesn't size to its text) and fills with `Interactions.HoldProgress` (developer decision).
- `Hud/SaveIndicatorView` (on `CombatHud.prefab`) fades in the `saving` ring (bottom right, icon only) for 1.2 s after each autosave.
- `Lore/LoreReaderScreen` (`LoreReader` child of `CombatHud.prefab`, sorting order 60, above pause) opens on `Core.Progression.LoreLogs.ReadRequested`: a green terminal panel with the log's title, author and scrolling body from the `Dialogue` table, Close or Cancel to leave; it locks creature control and plays an audio log's recording (the body is its transcript). `Lore/PickupToastView` on the same object shows a 2.5 s line (`pickup.*` keys) on `Collectibles.Found` and `LoreLogs.Collected`, and the arena clear line (`lockdown.humans` / `lockdown.machines`) on `ArenaEncounter.AnyCleared`.
- `Hoarder/HoarderScreen` (`HoarderMenu` child of `CombatHud.prefab`, sorting order 20) opens on `World.Hoarder.HoarderMerchant.TradeRequested`: a green terminal panel on the right with the Hoarder's subtitled chitter (`hoarder.*` in the `Dialogue` table: three greetings in turn, or `hoarder.empty` with no stock; `hoarder.buy` / `hoarder.poor` after a purchase), carried biomass and one row per mutation in stock (name, notches, effect, Buy). It locks creature control; Leave or Cancel closes it. From an eval: `HoarderScreen.Instance.Buy(id)`.
- `Run/MutationPickScreen` (`MutationPick` child of `CombatHud.prefab`, sorting order 25) opens from `Run/RunRewardHandler` on a Mutation or Challenge reward: three cards (name, notch dots, build tags from `MutationDefinition.Builds` as `mutation.build.*`, effect) drawn by `Core.Runs.MutationOffers` (weighted toward builds already equipped; seeded from the run seed, floor and step). Choosing grants and equips at once; when the notches are full it switches to a swap view of the equipped mutations, where marking enough to shed enables Shed and take. Take nothing / Back / Cancel; it locks creature control. From an eval: `Choose(i)`, `Toggle(id)`, `Confirm()`, `Back()`.
- `Run/PodScreen` (`Pod` child of `CombatHud.prefab`, `Pod.uxml` over the pick styles) opens on `Core.Runs.RunPod.Requested`, which `RunDirector` raises once the first room of a new run (not a resumed one) is set up: Weapon 1, Weapon 2 (or none) and the active ability (`SlotAbility`, or none) cycle through every weapon and slot ability in the content catalog until Mother's Call unlocks gate them (TV-246); Break out equips them and calls `RunPod.BreakOut`. It locks creature control; with no screen listening `RunPod.Request` breaks out at once. From an eval: `Cycle(row, dir)`, `BreakOut()`. The run autopilot's Skip breaks out too.
- `Run/EvolutionPickScreen` (`EvolutionPick` child of `CombatHud.prefab`, same `MutationPick.uxml`) opens on an Evolution reward, or on half of Challenge rewards while a weapon is open: cards of weapon modifiers from `Core.Runs.EvolutionOffers` (both options of one open weapon, or one from each). `RunRewardHandler.ApplyEvolution` grants and equips the modifier and recounts `RunSession.EvolutionsOpen`; with no open weapon the reward falls back to a mutation pick. Equipped modifiers clear on `RunSession.Started`. From an eval: `Choose(i)`, `Close()`.
- `Map/MapScreen` (`Map` child of `CombatHud.prefab`, sorting order 40): View (`GameplayInput.Map`: Select / M) toggles the full map; `GameplayInput.MapOverlay` (Tab / left-stick press, rebindable) toggles the overlay (developer decisions): a large, centred, 60% opacity map with no panel that follows the creature, which keeps control. Both hide while any menu is open or during fast travel (the overlay comes back after). Both use `Map/MapView`, a code-built element that draws the current sector registry's explored rooms in the sector colour, its markers (`map-marker--*` classes in `Map.uss`: grown nest, nest site, relay on/off, security door, blocked gate, Hoarder, pickup (yellow diamond) and lore log (blue), the last two hidden once collected, open tunnels (orange squares at both ends joined by a `map-link` line, shown once `ShortcutProgress.IsOpen`), every marker 16 px with a dark outline (developer decision: clearer markers), and the full map's legend (`MapScreen.LegendItems`, code-built from the same marker classes, keys `map.legend.*`; the full map only, developer decision), dropped biomass) and the creature; it rebuilds on open and on `MapProgress.Explored`, and only moves the creature dot per frame. The header shows the sector name and a `Security relays n/3` counter when the sector has relays. The pause menu's Map tab embeds a fitted `MapView` (`_mapStyle` adds `Map.uss` to the pause document). Scenes outside a registered sector show `map.noData`.
- `Map/TravelTransition` creates itself (persistent `UIDocument` on `Map/Resources/TransitionPanelSettings`, sorting order 500) on the first fast travel and draws a pulsing nest-colour cover from `FastTravel.Cover`. The nest menu's Travel tab (`ShowTab(3)`) lists every grown nest in the atlas (`<sector> · Nest n`, the current one marked) and `TravelTo(id)` closes the menu and travels.
- `Pause/PauseMenuScreen` (`PauseMenu` child of `CombatHud.prefab`, its own `UIDocument` with sorting order 50, between the nest menu and settings) opens on `GameplayInput.Pause` (Start / Esc) and closes on it or Cancel. It sets `Time.timeScale` to 0 (ending any hit-stop and rumble first), pauses the SFX bus (`Audio.AudioMix.SetPaused`; music and VO keep playing, so audio logs work from the Logs tab) and locks creature control. Pause stays fixed to Start / Esc (developer decision: not rebindable). It ignores Pause while the nest menu, settings or debug menu is open and for a frame after, so the Esc that closes one doesn't open it. Tabs: Map (the sector map), Abilities (loadout plus absorbed abilities), Mutations (notches, equipped and owned), Logs (collected logs in `LoreLibrary` order; each opens the reader over the pause menu). Quit to Main Menu / Quit Game confirm first; `PauseMenuScreen.InFight` (a boss alive, or an arena spawning or fighting) swaps the text for the warning that progress resumes at the last nest and skips the save, otherwise quitting saves. From an eval: `Open()`, `ShowTab(i)`, `AskQuit(toDesktop)` then `Confirm()`.
- `Hud/BossBarView` (on `CombatHud.prefab`) shows `Bosses.BossEnemy.Active` at the top: name from the `UI` table (`BossDefinition.NameKey`), health with a drain trail and phase ticks, and a stagger bar (pale blue while broken); it fades out after the boss dies. The `reward` label shows `boss.reward` ("Absorbed: {0}") for 3.5 s on `BossEnemy.Absorbed`.
- Nest menu notch pips (developer decision): the mutations list shows the notch pool as a code-built row of pips (`notch-pips`, `nest__pip` classes in `NestMenu.uss`) instead of the "Notches" text: filled = used; focusing or hovering a mutation button previews its change (green = would take, red = over the pool, faded = would free).
- `Map/SiteMapView` (on the full map, top right): the Site Beta floors (L0–L3 × 3) from `WorldGraph`, sectors coloured once any of their rooms is explored (else "Unexplored"), the current one outlined, and the current sector's routes with open or gate text (`map.route.*`, `map.gate.*`).
- `Hud/AbilityPromptView` (on the `CombatHud` root, code-built; developer decision) shows the Ability binding's glyph beside the creature, pulsing, while `AbilityController.IsReady` (equipped, affordable, not running, control free) and in combat (an `ArenaEncounter.Active` fight running or a live enemy within `_combatRange` 12 m).
- Consume prompt (developer decision): the enemy bar of the one enemy a Grab press would take now (`CreatureConsume.Target`, matched through `Enemy.ConsumeTarget`) shows the Grab binding's glyph (`InputGlyphLibrary.ForAction`, refreshed when the input device changes) above it; other feedable enemies only glow.
- `Nest/NestMenuScreen` (`NestMenu` child of `CombatHud.prefab`, its own `UIDocument` with sorting order 10) is the nest menu, a side panel that slides in from the right on `Nests.MenuRequested` and locks `CreatureMotor` control. Stats tab: biomass, next level cost and level, plus one row per stat with its live effect (`nest.effect.*` format strings) and a + button (`Stats.TryLevelUp`). Respec edits a `Core.Progression.RespecDraft` until every point is assigned, then `Stats.Respec`. Mutations is a locked tab until mutations exist. Back cancels the respec or closes the menu; control unlocks only once Grab is released, so the button that opened it doesn't grab. `InteractionPromptView` hides while it's open. Opening it sets the creature's charge to 0; closing it fills the charge to full only when an ability is equipped (developer decision). The tabs are buttons, Evolve (stats) and Loadout. Loadout shows Weapon 1/2 with Swap (`SwapWeapons`) and the ability slot with Change (`CycleAbility`: through the unlocked slot abilities in `Build.Abilities`, then empty), above the mutation list; owned weapons and their pickups come with TV-53, and Travel with the map (TV-81). The Upgrades tab (`ShowTab(2)`) shows Mutagen, each absorbed ability with tiers (tier, next tier's effect from `upgrade.<id>.tier<n>`, Evolve button: `UpgradeAbility(id)`) and each equipped weapon's modifiers (Unlock, then Equip/Remove: `ToggleModifier(id)`; unlocking equips it when the weapon has none). Its rows are `nest__upgrade` blocks with the effect on its own line: `nest__effect` has `flex-basis: 0`, which collapses a label's height in a column, so the block overrides it. The mutation list shows owned mutations (name, notch dots, effect text) with Equip/Remove, under a "Notches: used / pool" line. A mutation that doesn't fit is disabled. From an eval: `ShowTab(true)`, `ToggleMutation(id)`. From an eval: `NestMenuScreen.Instance.Plus(i)` / `BeginRespec()` / `ConfirmRespec()` / `Close()`.
- `Hud/LetterboxView` (on the `CombatHud` root, code-built bars inserted behind the other HUD elements) slides black bars (11% each, 0.35 s, unscaled time) in while `Core.Cutscene.Active` and out after. F5 HUD: "Letterbox (test cutscene)".
- `Credits/CreditsView` (on the `CombatHud` root, code-built) covers the screen in black when `Core.Finale.CreditsRequested` fires and scrolls the `credits.body` text (UI table) up over 24 s (`CreditsView.Scroll`, unit tested; unscaled time), with `credits.skip` at the bottom right; after 2 s South/Start, Space, Enter or Escape skips. It calls `Finale.FinishCredits` at the end.
- `Hud/OpeningSkipView` (on the `CombatHud` root, code-built) shows "Hold to skip" (`opening.holdToSkip`) with a `HoldRing` (a reusable `Painter2D` progress ring element) at the bottom right while `World.Opening.OpeningSequence.Playing`.
- `Hud/TutorialPromptView` (`Tutorial` child of `CombatHud.prefab`, sorting order 5, `Tutorial.uxml`) shows one first-time prompt at a time above the player bars (developer decisions): grab when an enemy within 8 m is feedable and dash when one within 12 m attacks (both stay up to 8 s), consume (4 s after the first grab), weapon 2 (after a weapon pickup, until slot 2 attacks), ability (equipped and charge covers it), nest (near an ungrown nest site) and attack (developer decision: no Move prompt). Each completes on use and is saved in `Core.Progression.Tutorials` (`WorldFlag.SeenTutorial`), so it never repeats in that save. The button shows as an icon from `Hud/InputGlyphs.asset` (`InputGlyphLibrary`: every filled 64 px glyph of the Kenney Input Prompts pack in `Assets/ThirdParty/KenneyInputPrompts/`, CC0; developer decisions: filled style, unknown pads show Xbox). `GlyphRules` (unit tested) picks the family (PlayStation by DualShock/DualSense names, Steam Deck by product name, else Xbox; keyboard and mouse for KBM) and maps the binding's effective (remapped) path to an icon name. Bindings without an icon (the WASD composite) fall back to bracketed text from the first binding (`TutorialPromptView.Glyph`). F5 HUD: Tutorial prompts on/off, Tutorials seen, Reset tutorials.
- `Hud/StatusIconsView` (on `CombatHud.prefab`) shows the creature's active statuses from `Combat.Status.StatusEffects` above the player bars: `status-slow` (purple square), `status-root` (gold diamond) and `status-stun` (pale blue circle, `CreatureVitals.IsStunned`), `status-bleed` (red square with one pip per stack, `StatusPips`), `status-burn` (orange dome) , `status-corrode` (green bowl) and `status-parasite` (violet leaf), placeholder shapes with no text. Enemy bars show the same bleed pips, burn, corrode and parasite dots and a cyan static bar in a row under the stagger bar, and under that one dot per weakness (white ring) and resistance (dim) from the `EnemyDefinition`, in the status colour, which pops when that status is applied.
- `Hud/SubtitleView` (on `CombatHud.prefab`) shows the current PA, radio or Crane line from `Audio.PaDirector` above the player bars: a speaker tag from the `Dialogue` table and the line, with a border colour per channel.
- `Hud/LowHealthScreenView` (on `CombatHud.prefab`) drives `Core.Rendering.LowHealthTendrilsFeature`. It sets the amount from the creature's health (creeping in at 0.6 a second, receding at 1.5), a heartbeat pulse (70 bpm light, 110 bpm heavy; none when `GameSettings.Flashes` is off), and a lurch that pulls the tendrils back 80% when `CombatEvents.ConsumeStarted` fires, creeping back over 0.9 s. F5 HUD tab: Low health screen (Auto, Off, Light, Heavy) and Low health effect on/off.
- `Hud/LoadoutHudView` (on `CombatHud.prefab`): weapon slots X and Y and the ability slot RT to the right of the player bars, showing each item's initials (`Initials`, unit tested) until icons exist. A slot with nothing equipped is dimmed (`hud__slot--empty`). The ability slot lights when charge covers its cost (`--ready`) and fills while it runs (`--active`). The biomass counter left of the bars updates on `Biomass.Changed` and pops a green or red delta (summed while it shows) for 1.6 s. Text changes only on events, so it allocates nothing per frame. Enemy status icons with stack counts wait for the first enemy statuses (bleed, burn, static, parasites).

## Debug menu

- F5 toggles it in the editor and development builds (`Debug.isDebugBuild`); release builds never create it. `DebugMenuHost` is created after the first scene loads (`DontDestroyOnLoad`) from `Debug/Resources/DebugMenu/` (`DebugPanelSettings`, `DebugTheme.tss`, `DebugMenu.uss`) and builds its tabs in code. While it's open, `GameplayInput` is disabled so clicks don't attack; the game keeps running (use the Game tab's time scale to slow or freeze it).
- Areas register commands through `Core.Debugging.DebugMenu` without referencing this assembly: `Button`, `Toggle`, `Slider`, `Value` (live text, refreshed 5× a second while open) and `Choice` (dropdown plus Go). Register from a static `[RuntimeInitializeOnLoadMethod(BeforeSceneLoad)]` method in a `<Area>DebugCommands` class, and resolve the current objects inside the callbacks (`CombatTargets.Creature`, `EnemyManager.Instance`), since scenes reload. Entries registered later (or removed with `DebugMenu.Remove`) rebuild the open menu.
- Tabs appear in the order Game, Creature, Combat, Enemies, Camera, HUD; new area names are appended. Current commands:
  - Game: version, FPS, scene, time scale, restart scene.
  - Creature: health, position, speed, dash chain, legs stepping, god mode, heal, take 25 damage, kill, teleport to spawn.
  - Combat: assist sliders (damage dealt and taken), hits landed, last hit.
  - Enemies: spawn (from `Enemies/Debug/Resources/DebugEnemySpawnList`; add new enemy prefabs to it), alive count, token use, freeze AI, stun all, bring all to 20% HP, kill all.
  - Camera: screen shake and flash toggles, room bounds.
  - HUD: show HUD, always show enemy bars.
- To open it from an eval, call `TentacleVania.UI.Debug.DebugMenuHost.Toggle()`, or queue an F5 `KeyboardState` on `Keyboard.current`.
